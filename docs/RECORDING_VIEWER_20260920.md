# 데이터 저장 복구 · 기록 열람 · 저장 시간

## 확인한 원인

실행 중인 SQLite DB는 정상이며, 기록은 시작되지 않은 상태였다. 기존 데이터는 2026-09-12 세션 1개, 28표본이었다. 공개 인터넷 화면은 `can_record=false`로 시작 버튼을 차단하고, `/api/control`과 `/records`도 로컬 전용으로 막았다. 또한 서버 재시작 시 활성 세션을 메모리에서 잃는 문제가 있었다.

## 변경

- `/api/records/control`은 인터넷에서도 저장 start/stop만 허용한다. 차량 제어 `/api/control`, 원본 DB API `/api/recording/*`의 로컬 제한은 유지한다. JSON 및 같은 Origin을 검사한다.
- `/records`는 별도 열람 화면이다. 이름·날짜 검색, 세션 목록, 1,000개 단위 고정 커서 페이지, yaw/전력/선택 채널 그래프, 표본 표와 측정값·센서 상태 JSON, 전체 세션 CSV를 제공한다. 원본 payload는 DB에 계속 보존하고 공개 API는 측정 채널을 명시적으로 선택한다.
- 저장 시작 시각과 경과 시간, 저장 건수, 수신 대기·DB 오류를 표시한다. 경과 시간은 서버 monotonic clock을 기준으로 브라우저에서 보간한다. 종료하면 멈추며, 실행 중 세션은 서버 재시작 후 시작 시각과 저장 건수를 복원한다. 재시작 중의 센서 미수신 시간을 제거하거나 채워 넣지 않는다.
- 시작/종료 버튼에 의해 이전 센서값이 중복 표본으로 저장되던 동작을 제거했다. 수신 처리 경로에서 저장하며 브라우저의 렌더링 주기에 의존하지 않는다.
- 기존 DB에 `received_at_utc`를 추가했다. 열람 시간축/CSV의 `elapsed_s`는 기록 시작부터 서버 수신까지의 시간이다. 원래 `captured_at_utc`와 보드 `source_timestamp_ms`도 보존한다. 구형 표본은 기존 captured 시각을 대체 기준으로 사용한다. 이 시간은 센서 자체의 측정 지연을 보정한 시간이 아니다.
- CSV는 세션 전체를 고정 상한 커서로 페이지 단위 스트리밍하며, 현재 화면 페이지에 제한되지 않는다.

## 검증

- 신규 기록 테스트 3개: 원격 시작/종료, monotonic timer, 종료 시 정지, DB 재열기 복구, 중복 없는 표본 수, DB 오류 시 허위 카운트 방지, 1,005개 전체 CSV, 비공개 데이터 제외, 차량 제어 접근 제한.
- 기존 gateway 34, tuning 8, battery 4, GNSS 7 테스트 통과. 전체 최초 실행에서 firmware UART 컴파일 시간 초과가 있었으나 해당 테스트 단독 재실행 통과.
- Edge headless: 신규 열람 화면 및 기존 피트·BMS 화면 통과. 원격 헤더, 모바일 너비, 페이지 이동, 다운로드, 기록 버튼, 타이머, 새로고침 검증.
- 실제 ngrok 주소에서 새 기록 세션 #2 시작 성공. 시작 시각 `2026-09-20T04:35:41.237Z` (한국 13:35:41). 공개 열람 HTTP 200.
- 적용 후 차량은 offline/transport NONE으로 표본 0개, 수신 대기. 실차 새 표본의 저장 증가 자체는 현재 확인할 수 없으며 인위적인 테스트 데이터를 운영 DB에 넣지 않았다. 연결 복구 후 활성 세션에 저장된다.
- SQLite quick_check=ok, 기존 세션 28표본 보존. 백업: `C:/Users/PARK/telemetry-audit-20260920/before-recording-fix.db`.
