# 서로 다른 인터넷망에서의 정밀 텔레메트리 개선

사용자 조건: 차량 ESP와 대시보드 PC가 서로 다른 네트워크에 있다. 로컬 UDP는 해결 경로로 선택하지 않는다.

## 확인된 병목

- 후방 제어는 100 Hz지만 `main.c`의 `dbg_div >= 20` 조건으로 ESP용 센서 상태 문장은 5 Hz만 생성한다. 대시보드가 차량의 100 Hz 원시 시계열을 받는 구조는 아직 아니다.
- 후방 USB `HAL_UART_Transmit`가 메인 루프의 IMU 파싱을 막았다. 앞선 계측의 gyro 입력 나이는 최대 약 32~42 ms였다.
- ESP는 HTTPS keep-alive를 이미 사용한다. 하지만 각 POST 응답 후 추가로 250 ms 대기한다. 연결을 재사용하는 것만으로 이 대기와 순차 요청/응답 구조가 없어지지는 않는다.
- 분석 화면은 250 ms 간격 폴링을 사용한다. 서버가 받은 모든 표본을 기록하는 것과 화면에 즉시 나타나는 것은 별개다.

## 이번에 준비한 수정

후방 USB 상태 출력을 `HAL_UART_Transmit_IT`로 변경했다. 송신 중인 버퍼를 덮어쓰지 않고, 진단 출력은 메인 루프에서 비동기 전송 완료 후 처리한다. UART1 무선 전달용 문장과 영점 9175는 유지한다. 부팅 보정 메시지의 동기 출력은 제어 타이머 시작 전이므로 이번 수정 대상이 아니다.

GCC 빌드 및 실제 IMU/제어 코드 회귀 테스트 통과. 빌드 크기 text 69760, data 180, bss 11624 bytes. **장치 미연결로 미적용, 개선 후 지연은 아직 실측하지 않았다.** SD flush 등 다른 메인 루프 작업의 최악 지연도 후속 계측이 필요하다.

## 권장 후속 구조 — 아직 구현하지 않음

`후방 100 Hz 표본 큐 → 압축된 UART 프레임 → ESP WSS 지속 연결 → 게이트웨이 기록 → 브라우저 push`

1. 제어 틱마다 필요한 yaw/목표 yaw/error/조향/TPS/RPM/출력과 후방 기준 취득 시각을 기록한다. 큐는 ISR에서 짧게 쓰고 메인 루프/DMA가 전송한다. 고속 채널과 느린 BMS/상태 정보를 분리해 큰 JSON 전체를 매 틱 보내지 않는다.
2. UART에는 버전, 길이, sequence, timestamp, CRC가 있는 고정 형식 프레임을 사용하고 두 장치에 맞춰 baud를 정한다. 현재 긴 문자열을 그대로 100 Hz로 올리는 것은 대역폭을 초과할 수 있다.
3. WSS를 한 번 연결해 유지하고 응답마다 다음 전송을 막지 않게 한다. 100 Hz 표본을 2개씩 약 20 ms 단위로 보내는 것을 초기 설계 목표로 한다. TLS 인증서/호스트 검증과 차량 인증은 유지한다. 재연결·ACK·재전송·중복 제거도 필요하다.
4. 서버는 원시 표본 100 Hz를 보존하고 화면은 20~30 fps로 그린다. 최신 표시가 과거 재전송 적체를 기다리지 않게 하되, 기록 재전송과 결측은 별도로 추적한다. 유한 RAM만으로 장시간 통신 단절 중 무손실을 보장할 수 없으므로 저장 용량과 overflow 상태를 노출해야 한다.
5. 정확도는 도착 시각이 아닌 차량의 취득 시각으로 유지한다. 평균/P95/최대 데이터 나이, sequence 누락, 큐 깊이, 동기화 오차 추정치를 함께 측정한다. 1 µs 타이머 해상도는 1 µs 절대 정확도 보장이 아니다. 현재 HSI의 상대 skew와 절대 시간 오차도 구분한다.

20 ms 전송 간격 및 화면 갱신률은 목표값이다. 인터넷 구간의 최악 지연은 보장할 수 없으며 실제 두 네트워크에서 end-to-end P95와 최대값을 검증해야 한다. 토크벡터링 폐루프 제어는 차량 내부에서 실행한다.

[ngrok 공식 문서](https://ngrok.com/docs/using-ngrok-with/websockets)는 기존 HTTP endpoint에서 별도 ngrok 설정 없이 WebSocket을 지원한다고 명시한다. [Espressif WebSocket client](https://components.espressif.com/components/espressif/esp_websocket_client/versions/1.7.0/readme?language=en)도 제공되지만, 현재 Arduino/PlatformIO 빌드에 통합하는 작업과 검증은 아직 하지 않았다.
