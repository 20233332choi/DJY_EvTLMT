## 사용법

`/records` 또는 `/analysis`에서 세션을 고른다. 서버의 1,000개 페이지를 모두 읽어 고정된 세션 범위를 만든다. 조회 중 추가되는 기록은 '최신 저장분 다시 읽기'로 반영한다.

- 배터리, 모터 출력 요구, TV/yaw/PID, 구동/RPM/차속, 조향/스로틀, 셀 전압, GPS로 분류했다. 신호별/카테고리별 체크박스 및 배터리/TV 표시 프리셋을 제공한다. 해제해도 DB 데이터는 삭제하지 않는다.
- 배터리 전력은 W로 표시하며 팩 전압×전류의 원본 부호를 유지한다. 선택 카드에 절댓값과 BMS 충전/방전 상태를 함께 표시한다. 모터 출력 요구값은 '실측 아님'을 명시한다.
- 동일 단위의 신호는 함께 표시하고, 단위가 다르면 별도 Y축 그래프로 나눈다. 전체 그래프의 X축 구간과 선택 커서는 동기화된다.
- X축 기준은 기본 '표본 시각'이며 '서버 수신 시각'으로 전환할 수 있다. 두 값 모두 저장 시작 시각 대비 초 단위다. 표본 시각은 기존 게이트웨이의 captured_at_utc 환산값이며 센서간 완전한 동시 측정을 뜻하지 않는다.
- 드래그/휠 확대, Shift+드래그 및 이동 버튼, 더블클릭 전체 구간, X 최소/최대 직접 입력, 각 Y 최소/최대 및 자동 범위를 지원한다.
- 클릭하면 실제 저장 표본에 커서를 고정한다. 방향키/표본 버튼/슬라이더/표 행으로 이동하며 시각(밀리초 표시), 단위별 값, 원본 JSON을 확인한다. 포인터 위치와 선택 표본 X를 구분한다.
- '구간 최대 |W| 지점'은 현재 X 구간에서 전력 절댓값이 최대인 실제 표본을 선택한다. 충전과 방전을 모두 비교하므로 BMS 상태를 함께 확인한다.
- OSM 지도는 GPS가 있는 저장 표본만 그린다. 선분 색은 끝점 표본의 전력 크기 |W|이며 원본 부호는 선택 카드에 남는다. 경로 클릭 시 해당 표본으로 이동한다. GPS 정확도/표본 나이/측정 시각을 함께 표시한다.
- 원시 배열 및 CSV에는 전체 표본을 유지한다. 그래프만 픽셀별 first/min/max/last를 그려 짧은 피크를 보존하며, 표본 표는 200개씩 이동한다. 동일 시각의 여러 표본도 전체 구간 끝에서 빠지지 않도록 upper-bound를 사용한다.
- 전체 CSV에 W 단위 출력 요구, GPS 메타데이터, 최대 48셀 전압, 표본 시각 기준 elapsed를 추가했다. 기존 kW 열은 유지한다. 미수신은 공백/null이며 실제 0과 구별한다.

## 검증 및 적용

- 기록 API 테스트 3개 및 게이트웨이 테스트 34개 통과.
- `scripts/check_analysis_browser.py`: 1,007표본 전체 로드, 첫 1,000개 밖의 음수 방전 피크, 동일 타임스탬프, 0/미수신 구분, GPS 연결/미수신 마커 제거, X/Y 범위, 드래그 확대, 체크박스/프리셋, 원본 유지, 전체 CSV, 모바일 레이아웃, 기록 시작/종료 검증 통과.
- 기존 `check_records_browser.py`는 확장된 분석 테스트 진입점으로 연결했다.
- 운영 DB 2,266표본 백업: `C:/Users/PARK/telemetry-audit-20260920/before-analysis-ui.db`.
- 공개 `/records` HTTP 200 및 Edge 브라우저 검증. 실제 세션 #3의 1,885표본 전부를 조회했으며 JavaScript 오류 없음.
- 실제 세션 #3 최대 |W| 표본: ID 231, 표본 시각 기준 T+42.059초, **−9,004.21W**, BMS `DISCHARGING`. 원본은 50.9V × −176.9A. 이는 방전 전력 크기 9,004.21W이며 코드상의 모터 출력 요구값과 다르다.
- 기존 세션 #1/#3/#4에는 유효 GPS 저장값이 0개였다. 기존 기록의 물리적 지도 위치를 추정해 만들지 않는다. 이후 GPS를 함께 수신·저장한 세션부터 지도 연동이 가능하다.

게이트웨이 적용 전 차량 제어/랩 측정 비활성을 확인했다. 기록 세션을 임의로 시작하거나 모터 펌웨어를 변경하지 않았다.
