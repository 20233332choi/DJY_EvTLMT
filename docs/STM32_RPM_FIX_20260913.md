# STM RPM 고속 잡음 오인식 수정 — 2026-09-13

상태: **소스 수정·PC 회귀시험·ARM 빌드 및 Rear STM 적용/읽기 검증 완료.**
컨트롤러 구동 전원 차단 확인 후 적용했다. 실제 회전 RPM의 정확도 검증은 아직 하지 않았다.

## 원인과 수정

기존 `rpm_sensor.c`는 너무 짧은 캡처 간격을 버리면서 마지막 캡처 기준은 갱신하지 않았다.
연속 잡음 입력이 약 11.9ms까지 누적되면 정상 주기로 인정되어 약 8,000RPM을 만들었다.
잡음이 지속되어도 마지막 인정 시각이 갱신되어 `RPM_IsFresh()`가 true가 되는 문제다.

이번 수정:

- 매 캡처마다 기준을 갱신하여 빠른 잡음의 시간 누적을 차단한다.
- 시작·타임아웃·잡음 이후 정상 범위의 주기 2회(에지 3개)가 있어야 유효 RPM으로 인정한다.
- 무효 입력과 400ms 초과 미수신은 유효성 false로 처리한다. 필터의 이전 RPM을 제거한다.
- 첫 에지는 시간 기준일 뿐이며, 수신 1건만으로 fresh를 인정하지 않는다.
- 긴 입력 공백에서 틱→마이크로초 곱셈 전에 범위를 검사한다. TIM2 및 시스템 시간 wrap을 시험했다.
- 좌우 상태를 독립 처리하고 짧은 원자적 조회 시 호출자의 인터럽트 마스크를 보존한다.
- UART 로그 끝에 `rv=좌/우`(0=무효, 1=유효)를 추가한다. 기존 L/R/cap/glt 필드 형식은 유지한다.
- PC 유선 파서는 `rv=0`인 측정치를 정상 RPM으로 표시하지 않지만 원본 값·로그는 보존한다.
- 잡음으로 0이 된 값을 정차 증거로 사용하지 않도록, 피트 설정 적용 조건에
  `!RPM_HasRecentActivity()`를 추가했다. 잡음 캡처도 최근 활동에 포함한다.

## 변경하지 않은 부분

수정 전후 실제 빌드 트리의 토크벡터링·PID·전자식 디퍼런셜·Safety_Update·DAC 출력 코드,
RPM 보정 상수 및 GPIO/타이머 초기화 코드는 동일하다. TV/ED 활성화 정책을 새로 완화하거나
원격 제어를 활성화하지 않았다. ESP 펌웨어와 ngrok 설정은 변경하지 않았다.
보드 적용 후 유선 파서 반영을 위해 COM13 게이트웨이만 읽기 전용 모드로 재시작했다.

펄스가 없다는 사실만으로 정차/단선을 구별할 수는 없다. 무효 RPM의 숫자 0은 실제 0RPM 측정이
아니다. 조용한 상태에서의 피트 설정 역시 기존 물리 PIT ENABLE 등 다른 조건을 필요로 한다.

## 실제 적용 및 유선 확인

- 사용자에게 컨트롤러 구동 전원 차단 완료 확인을 받고 진행했다. 모터 구동/스로틀 시험은 요청하지 않았다.
- 대상: Rear COM13, ST-Link `066BFF495151834987243052`, DBGMCU ID `0x10006421`, flash 512KiB.
- 적용 직전 전체 플래시를 `.local/stm32-rpm-preflash-20260913-full.bin`으로 백업했다.
  앞 40,456바이트의 SHA256이 위 기존 이미지와 일치하여 대상/버전 변경이 없음을 확인했다.
- OpenOCD Programming/Verify 성공 후 재부팅, 상태 running 확인.
- `.local/stm32-rpm-postflash-20260913.bin`으로 다시 읽은 40,652바이트가 적용 이미지와 SHA256까지 일치했다.
- 재시작 전 Scope 12,020개 샘플을 `.local/rpm-preflash-20260913-scope-*.json`에 보존했다.
  수신이 진행 중인 페이지별 스냅샷이며 DB 측정 세션은 아니다. 당시 recording_active=false였다.
- 유선 게이트웨이를 `--rear-serial COM13 --http-host 127.0.0.1`로 재시작했다.
  무선/릴레이 입력 및 원격 제어는 계속 비활성이다.
- 재시작 후 서로 다른 sequence 50개를 관찰했다. 수신 약 5.04Hz, 최대 관측 age 204ms.
- 50개 모두 L/R 보고값 0, `rv=0/0`. 왼쪽 `NO_PULSES`, 오른쪽 `NOISY`로 표시됐다.
- 관찰 구간 오른쪽 캡처 116,670개 증가, 폐기 116,670개 증가: 그 구간의 캡처는 모두 폐기됐다.
  적용 전 같은 정지 벤치 상태에서 보고되던 약 7,979RPM은 관찰되지 않았다.
- Scope의 실제 RPM 값은 좌우 모두 null(무효), STM 보고값은 0으로 보존됐다.
  실제 회전수가 0이라고 측정/보증한 것이 아니다.
- TV/ED=false, TPS 개도량 0% 유지. IMU와 조향각 유효 수신은 현재 확인되지 않았다.
- 적용 후 증거: `.local/rpm-postflash-20260913-telemetry.json`,
  `.local/rpm-postflash-20260913-scope.json`, 게이트웨이 stdout/stderr 로그.

## 남은 작업 및 재적용 시 조건

1. 플래시 직전에 구동 전원 또는 컨트롤러로 가는 스로틀 출력의 물리적 분리를 확인한다.
2. 대상 STM을 다시 식별하고 변경 여부/백업을 확인한 뒤에만 후보를 적용한다.
3. 이후 유선 파서 변경으로 재시작할 때도 진행 중인 측정/버퍼를 먼저 보존한다.
4. 실제 입력으로 cap/glt/rv와 파형을 비교하고, 알려진 펄스 또는 독립 RPM 기준으로 정확도를 검증한다.
5. 이번 수정은 전기적 잡음 발생원, 컨트롤러 출력 모드/보정 정확도, STM→ESP 배선 문제를 해결했다는 뜻이 아니다.
6. 같은 날 후속 작업에서 ESP에 `rv` 유효성 해석을 추가하고 무선 PC 전달을 확인했다.
   Scope 실제 RPM은 무효일 때 null, STM 보고값은 별도 채널에 보존된다.
   [STM→ESP→핫스팟 무선 검증](ESP_UART_UDP_20260913.md)을 참고한다.

정상 인정 지연은 시작/복구 시 에지 3개까지다. 정상 동작 중 계산식·출력 필터는 유지한다.
안전 판정상 RPM이 무효이면 기존 경로로 TV가 차단될 수 있으며, 이를 우회하지 않는다.
