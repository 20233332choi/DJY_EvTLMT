# USB 전체 표본 기록과 전방 소스 정리

## 적용

ESP32-S3의 기존 **USB-UART 포트**를 유지한다. ESP 펌웨어와 Python 게이트웨이를 함께 업데이트한다.
ESP USB 통신은 **3,000,000 baud, 8N1**이고, 기존 초당 1개 디버그 출력 제한을 제거했다.
후방 STM→ESP는 460800 baud, 후방 STM의 ST-Link USB 진단은 115200 baud/최대 5 Hz를 유지한다.
여기서 전체 표본 수집용 USB는 **ESP의 USB-UART**다.

로컬 PC에서 실행:

```powershell
python gateway/ev_gateway.py --serial COM8
```

기존 인터넷 실행기와 함께 사용:

```powershell
.\start_telemetry.bat -EspPort COM8
```

COM8은 실제 ESP USB-UART 포트로 바꾼다. `--serial`의 기본 baud는 3000000이며
`--rear-serial`은 115200이다. 기존 펌웨어를 점검할 때만 `--baud 115200`을 명시한다.
기록은 웹에서 **측정 시작**을 누른 시점부터 DB에 저장한다. USB 모드에서도 UDP와 HTTPS 수신이 가능하다.

Espressif의 [ESP32-S3-DevKitC-1 설명](https://docs.espressif.com/projects/esp-idf/en/v5.2/esp32s3/hw-reference/esp32s3/user-guide-devkitc-1-v1.0.html)은 USB-UART 브리지 최대 3 Mbps를 명시한다.
실제 보드의 브리지 칩·드라이버·케이블에서 이 속도로 안정적으로 동작하는지는 연결 시험이 필요하다.
플래시 업로드 속도는 변경하지 않았다.

## 전송·재전송

- ESP가 받은 후방 표본마다, BMS 0x90 응답마다 동일한 원본 이벤트를 USB와 무선 경로에 제공한다.
- USB는 최소 50 ms 간격으로 최대 32개를 묶는다. 전송·ACK가 오래 걸리면 간격이 늘어나며, 각 표본의 원래 시각과 값은 유지한다.
- 최초 연결/재연결 때 필드 이름 배열을 보내고, 이후에는 값 배열만 전송한다. 같은 JSON 필드의 숫자·배열·진단값을 보존한다.
- 프레임은 JSON 본문 뒤에 탭, CRC16 4자리, LF를 붙인다. CRC-16/CCITT-FALSE, 초기값 `0xffff`, 본문 전체가 검사 대상이다.
- UART에는 여유 공간만큼 나누어 쓰므로 센서 수신 루프가 USB 전송을 기다리지 않는다. 실행 중 진단 문장이 프레임에 끼어들지 않도록 주기적인 콘솔 출력을 제거했다.
- PC의 `usb_start`로 전송을 시작한다. 데이터가 2초간 오지 않으면 다시 요청해 ESP만 재부팅된 경우도 복구한다.
- 기록 중에는 DB 묶음 COMMIT 이후 `usb_ack`를 보낸다. 기록 대기 중에는 실시간 수신 처리 완료를 확인한다. USB ACK는 차량 제어 명령이 아니다.
- CRC 오류나 DB 실패에는 ACK하지 않는다. ESP는 미확인 표본을 유지하고 약 1초 후 재전송한다.
- USB FIFO는 **48 KiB/최대 96개**, 무선 FIFO는 기존 **96 KiB/최대 256개**다. 가득 차면 새 표본 누락을 센다. 장시간 단절이나 전원 차단까지 보존하는 저장장치는 아니다.

## 같은 표본을 한 번만 기록

ESP 부팅 ID와 표본 sequence를 USB·UDP·HTTPS에서 공유한다. 서버는 경로 우선순위로 고속 데이터를 버리지 않고,
이미 받은 표본만 중복 제거한다. 늦게 도착한 표본이 이전 누락 구간을 채울 수 있다. ACK는 해당 묶음의 마지막 sequence다.
지연된 표본은 DB와 그래프에 추가하되 최신 차량 값을 과거로 되돌리지 않는다. 그래프는 표본 시각순으로 그린다.

DB 묶음이 성공한 뒤에만 피트/BMS 그래프 버퍼에 표본을 추가한다. 삽입 오류와 최종 저장 오류 모두 상태에 표시하고,
실패한 묶음을 다시 받아도 그래프가 두 배로 증가하지 않는다. 화면 전달용 UDP 실패는 완료된 DB 저장을 취소하지 않는다.
부팅 ID 중복 제거 상태는 서버 실행 중 유지되며, 서버 재시작을 넘는 영구 중복 제거는 구현하지 않았다.

## 전방 STM

제공본을 `firmware/stm32_front_synced`에 포함하고 `-BinaryRear` 빌드가 이 전방과
`firmware/stm32_rear_binary` 후방을 선택하도록 연결했다. 기존 외부 PC 경로를 보던 시간 동기화·F1 진단·차량 좌표계 검사는
저장소에 포함한 소스를 직접 검사한다. 기존 센서·모터 제어 알고리즘은 변경하지 않았다.

## 검증

- 실제 ESP formatter의 48셀·긴 진단값을 소수점 출력 폭까지 유지해 3 Mbps 선로, 4096바이트 UART 버퍼, PC ACK 지연 10 ms를 모의했다. 200 표본/s로 발생시킨 2,000개가 모두 전달·저장됐다.
- 부분 쓰기, ACK 유실, CRC 손상, 잘린 수신, 과대 프레임 후 복구, 스키마 재사용과 DB 실패 후 재전송을 검사했다.
- USB·UDP·HTTPS가 중복/지연 수신한 1,000개 표본이 DB와 피트/BMS 그래프에 각각 한 번씩 남았다.
- 전방·후방 공통 시간 소스 5개 일치, 시간 동기화·F1 버퍼·차량 좌표계 검사 통과.
- 보드 플래시·연결 주행 시험은 수행하지 않았다. 10 kW 제한이나 센서 오류 대응 알고리즘은 이번 수정 대상이 아니다.
