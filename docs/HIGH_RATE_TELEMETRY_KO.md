# 고속 수집·묶음 전송·전체 기록 조회 (2026-09-21)

웹 화면의 갱신 빈도와 표본 수집 빈도를 분리했다. 받은 표본을 평균이나 마지막 값으로 축약하지 않고 FIFO에 담아 여러 개씩 보낸다. 후방 STM, ESP, Python 게이트웨이, 웹페이지가 변경 대상이다. 전방은 제공본 `stm32_front_synced`를 포함해 빌드 대상을 연결했다. 센서·모터 제어 로직은 변경하지 않았다.

## 현재 경로

| 구간 | 동작 |
|---|---|
| 후방 STM 제어 | 기존 100 Hz 유지 |
| 후방 → ESP | 제어 tick 종료마다 전송 요청, 5 → **100 Hz**. 238바이트·460800 baud 유지 |
| ESP USB-UART | 3000000 baud, 무선과 같은 이벤트를 최대 32개씩 묶어 전송. CRC·DB ACK·재전송. [상세](USB_RECORDING_KO.md) |
| STM USB ASCII | 최대 5 Hz 유지. 느린 진단 출력이 UART1 빈도를 제한하지 않음 |
| BMS → ESP | 0x90을 독립적으로 10 ms마다 요청. 정상 응답마다 별도 표본 보관 |
| ESP → 인터넷 | 한 요청에 최대 **64개**, 실제 본문은 **64 KiB** 이내. 요청 시작 간격 최소 **200 ms**, HTTP 수행 시간 포함 |
| 서버 저장 | 표본별 원래 시각 간격 유지. 한 묶음을 SQLite 트랜잭션 하나로 저장. 재전송 중복 제거 |
| 웹 | 응답 완료 후 100 ms 뒤 다음 조회. 밀린 페이지는 즉시 이어 조회. 화면 정지 중에도 표본 수집 계속 |

`sample_kind`는 `rear`, `bms`, `heartbeat`를 구분한다. STM 100 Hz, BMS 실제 응답 100 Hz라면 합계 약 **200 표본/s**다. BMS만 갱신된 표본에서는 STM 값과 STM source sequence가 이전과 같을 수 있다. 이는 새 STM 측정을 뜻하지 않는다. 모든 센서가 같은 순간에 취득된 것도 아니다. BMS 내부 측정 주기는 별도 실측해야 한다.

후방의 스냅샷·CRC·송신 처리는 메인 루프에서 실행한다. 루프 지연이나 UART busy로 놓친 제어 tick을 보간하거나 복원하지 않는다. `rear_sample`의 원본 sequence·누락 진단을 확인해야 한다. 100 Hz에서 UART 선로 점유율은 약 **51.65%**이고, ISR/메인 실행시간은 실보드의 timing 진단으로 확인해야 한다.

## 전송 크기와 보관 한계

기존 전체 JSON의 필드 이름을 매 표본마다 반복하지 않는다. `columns`에 키 목록을 한 번 보내고 `samples`에 값 배열들을 보낸다. 서버가 원래 키/값 객체로 복원한다. 소수 자리·불리언·배열·원본 진단 필드는 그대로이며, 기존 객체 배열 방식도 서버에서 받는다. 펌웨어의 실제 JSON을 분리·복원한 테스트에서 모든 필드가 일치했다.

ESP FIFO는 **96 KiB**, 표본 메타데이터 슬롯은 최대 **256개**다. 각 값 배열은 최대 1535바이트다. 한도가 차면 기존 미확인 표본을 유지하고 새 표본의 누락을 센다. 요청 실패/ACK 유실 때 기존 표본을 재전송하며, ACK된 구간만 비운다. 전원 차단 후 보존하는 저장장치는 아니다.

보관 시간은 `98,304 / 실제 행 바이트 수 / 초당 표본 수`로 계산한다. 예를 들어 행이 700바이트이고 200 표본/s이면 약 **0.70초**, 100 표본/s이면 약 **1.40초**다. HTTP 송신 중인 표본도 이 버퍼에 남으므로 전부가 추가 단절 여유는 아니다. 무제한 단절·지속적인 전송 속도 부족에 대해 무손실을 보장하지 않는다. 더 긴 단절을 전부 보존하려면 SD/PSRAM 등 저장 자원을 검토해야 한다.

64 KiB 안에 들어가는 행 수만 보내므로 실제 묶음 크기는 64보다 작을 수 있다. HTTPClient의 Stream 전송으로 FIFO에서 조금씩 읽어 보내며, 전체 본문을 별도 대형 버퍼로 복사하지 않는다. 송신 중에도 새로운 표본을 FIFO의 남은 공간에 추가할 수 있다.

고정 4개/250 ms 구조는 제거했지만 실제 처리량은 이동통신 지연·업로드 속도·서버 처리량에 달려 있다. 화면에 표본/s, 최근 묶음 개수, 송신 시 대기 개수, 최신 표본의 전송 대기 시간, ESP/STM/UART 누락을 표시한다. 전송 대기 시간은 ESP 버퍼 체류 시간이며 이동통신 전체 왕복 지연이나 BMS ADC 지연이 아니다.

## 웹에서 모든 기록 보기

1. 피트 또는 인터넷 화면에서 **측정 시작**을 누른 뒤 주행한다. DB 기록은 이 시점부터다.
2. `/pit`에서 실시간 그래프를 보거나 과거 세션을 선택한다. 배터리 전압·전류·실측 전력과 횡·종가속도 그래프를 추가했다. 방전 전류·전력은 기존 DALY 부호대로 음수다.
   - 마우스를 올리면 모든 그래프가 같은 표본 시점을 표시하고, 각 그래프 위에 신호별 값·단위를 보여준다.
   - 좌클릭하면 해당 표본의 **표시값만 고정**한다. 그래프와 시간축은 계속 갱신되며, 표본 수집과 진행 중인 DB 기록도 계속된다. 선택 표본이 표시 구간이나 최근 버퍼를 벗어나도 고정값은 유지한다. 세로선은 그 시점이 표시 구간 안에 있을 때만 보인다.
   - 그래프를 멈추려면 별도의 **화면 일시정지** 버튼을 사용한다. 과거 시간 탐색 중에는 기존처럼 화면을 정지한다.
   - 다른 지점을 클릭하면 고정 시점이 바뀐다. **실시간 보기 / 실시간 재개**는 고정을 해제하고 최신 화면으로 돌아간다. 조회 구간·시간 탐색·과거 페이지를 바꾸면 시점 선택은 해제된다.
3. 과거 세션의 **세션 전체 CSV 저장**은 현재 페이지 밖의 표본까지 포함한다. 실시간 화면의 CSV는 브라우저 최근 버퍼만 포함한다.
4. `/records`는 최신 원본 저장소의 분석 화면을 유지한다. 전체 세션을 읽고 카테고리·공통 시간축·구간 확대·지도·200개 단위 표본 표로 조회한다. 조회 끝 ID를 고정하므로 새 기록이 기존 페이지를 밀지 않는다. **최신 저장분 다시 읽기**로 범위를 갱신한다.
5. **전체 세션 CSV**는 공개 측정 채널을 포함한다. 로컬 피트 PC의 **원본 JSONL**은 각 행의 ID·취득 시각·모든 원본 필드를 페이지 단위로 전송한다. `/api/recording/export?session_id=번호&format=csv`는 `payload_json`도 포함한 원본 CSV를 제공한다.

인터넷에서는 기존 측정 채널 조회와 기록 시작·종료를 유지한다. 모든 원본 필드 다운로드와 차량 제어에는 기존 로컬 접근 제한이 적용된다. 라이브 버퍼는 서버·브라우저 각각 최근 **12,000 표본**이며 초과 구간은 저장한 세션에서 조회한다.

### BMS 전용 페이지

`/battery`는 최신 저장소의 배터리·출력 요구·TV·차속 등을 포함한 **그래프 11개**를 유지하며 같은 시점 선택 기능을 적용했다. `/api/battery/live`에서 수집된 표본을 순서대로 받고, 응답 후 100 ms마다 조회하며 밀린 표본은 즉시 이어 받는다. 기존 피트 그래프의 표본 시각·누락/미수신 처리 방식을 재사용한다.

좌클릭하면 위 숫자 카드와 그래프별 표시값만 고정된다. 그래프와 시간축은 계속 움직이며, 선택 표본이 최근 버퍼를 벗어나도 값은 유지한다. **실시간 보기**로 해제하고, 그래프 자체를 멈추려면 **화면 일시정지**를 사용한다. 아래 **현재 셀 전압 / 현재 BMS 상태 및 알람**은 별도로 현재값을 갱신한다. 유선 DALY UART 입력도 해당 입력의 값과 수신 시각으로 그래프에 반영한다.

일반 실행에서는 보드 미연결 시 미수신으로 표시한다.

## 적용과 확인

USB 전체 표본 수집과 다중 경로 중복 제거는 [USB 기록 안내](USB_RECORDING_KO.md)를 따른다. 서버·웹을 먼저 업데이트하고 `firmware/stm32_rear_binary` 후방과 ESP를 함께 적용한다. 후방 빌드는 `scripts/build_stm32_rear_uart.ps1 -BinaryRear`로 선택한다. 실제 ESP의 Wi-Fi/relay 설정은 제공되지 않아 시험용 설정으로 빌드했다. 보드 업로드 및 이동통신 실차 시험은 하지 않았다. 실측 전력에 따라 후방 출력을 제한하는 기능도 이번 작업에 포함되지 않는다.

- 펌웨어의 실제 JSON 분리·복원, 48셀/최대 폭 진단값 보존, 가변 길이 FIFO wrap/초과/ACK/재시도 검사.
- 모의 200 표본/s, 10초 동안 2,000 표본을 넣고 한 번의 전송 실패 이후 FIFO 전송 완료 확인.
- 64행 묶음의 시간 간격, 중복 재전송, 잘못된 schema/마지막 행 거부 검사.
- 1,100개 이벤트가 각각 DB에 남고, 재시도는 추가 행을 만들지 않으며 전체 다운로드와 고정 페이지가 모든 행을 반환하는 HTTP 시험.
- 최신 원본 92개 중 82개 통과, PR 적용본 106개 중 102개 통과. 기존 실패 4개가 남아 있으며 새 실패는 없다. 자세한 내용은 [검증 기록](PR_VALIDATION_20260921.md)을 참고한다. Stream 본문 길이·분할 읽기·송신 중 표본 추가도 검사했다.
- 실제 Chrome에서 그래프 13개, 과거 세션 1,010개 표본의 페이지 이동·전체 다운로드, 화면 정지 중 새 표본 40개 수집, 모바일 피트 화면 및 브라우저 오류 없음 확인.
- ESP32-S3 실제 툴체인 빌드: 정적 RAM 215,436 / 327,680바이트(65.7%), Flash 939,269 / 3,342,336바이트(28.1%). 남은 RAM은 네트워크/TLS/스택 등의 동적 메모리와 공유하므로 실행 중 여유 확인이 필요하다.
- 후방 STM 변경 소스 재컴파일 및 47개 오브젝트 링크 성공.

실차에서는 source 누락, UART 오류, ESP 누락이 증가하지 않는지와 제어 실행시간·BMS 수신 간격·실제 인터넷 전달률을 함께 확인한다. 브라우저 표본/s는 STM과 BMS 이벤트의 합계이므로 STM 제어 주파수로 해석하지 않는다.
