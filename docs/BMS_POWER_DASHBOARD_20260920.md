# BMS 전력 화면 및 차속 보정 — 2026-09-20

## 적용 내용

- `/battery`를 기존 피트 화면과 같은 스타일의 분석 화면으로 교체했다. 팩 전력 W/kW, 전압·전류·SOC, 셀 전압·편차·온도·상태를 표시한다.
- 팩 전력은 같은 수신 패킷에 포함된 유효한 전압 × 전류로 계산한다. 전류 부호를 유지하며, 유효한 0 A는 0 W이다. 값이 없거나 오래되면 미수신으로 표시하고 DB 전력 열에도 NULL을 저장한다.
- 팩 전체 전력과 좌우 모터 출력 요구값을 구분한다. 모터별 실제 소비전력은 현재 제공되지 않는다.
- 토크벡터링 ΔP, 목표/실제 yaw rate, TPS, 차속과 같은 표시 시간축에서 비교할 수 있다. 전압·전류·전력의 표시 구간 시작 대비 변화도 보여준다.
- 피트 화면과 같은 기록 세션을 사용한다. 기록을 시작한 동안 수신 샘플을 저장하며, 과거 기록 탐색과 표시 페이지 CSV 내보내기를 지원한다. 화면 일시정지는 수집을 중단하지 않는다.
- 외부 공유 화면은 읽기 전용이다. 기록 시작·종료는 피트 PC에서 한다.

## 차속 기준

사용자가 확인한 타이어 포함 전체 지름은 0.45 m, 감속비는 4:1이다.

`차속[km/h] = ((좌 모터 RPM + 우 모터 RPM) / 2) / 4 × π × 0.45 × 60 / 1000`

평균 모터 RPM 1,000이면 약 21.21 km/h이다. 게이트웨이는 유효한 좌우 RPM이 들어올 때 이 기준으로 표시 차속을 계산한다. STM이 보낸 원래 `vehicle_speed_m_s`는 보존한다. 바퀴 미끄러짐이 있으면 실제 지면 속도와 차이가 난다.

ESP 소스의 차속 상수와 실제 작업 중인 `C:\Users\PARK\Documents\TV\stm_back\Core\Inc\vehicle_params.h`의 반지름도 0.225 m로 맞췄다. 저장소의 과거 STM 사본 `firmware/tv_stm_esp/stm_back`은 이번에 동기화하지 않았다.

## 측정 한계

BMS 요청은 현재 9개 항목을 100 ms 간격으로 순환하므로 동일 항목 요청 간격은 약 0.9초이다. 빠른 차량 패킷에 같은 BMS 값이 반복돼도 새 BMS 측정으로 간주하면 안 된다. 이번 변경은 BMS 요청 속도나 센서 시계 동기화를 바꾸지 않는다. 그래프의 같은 시간축만으로 센서 측정 시각이 일치한다고 해석하면 안 된다.

게이트웨이의 BMS 값 만료 처리는 필드가 포함된 수신 패킷 기준이다. ESP가 캐시한 값을 반복 전송하는 경우 개별 CAN 항목의 실제 측정 시각까지 판별할 수는 없다.

## 검증 및 적용 상태

- Python 전체 79개 테스트 통과. 이후 DB NULL 저장 보완 후 관련 38개 테스트 재통과.
- 피트 화면 브라우저 회귀 검사 통과. BMS 화면은 전력·과거 기록 페이지·CSV·모바일·일시정지·통신 단절 검사를 통과했다.
- STM 및 ESP 펌웨어 빌드 통과. 장치 미연결로 새 펌웨어는 아직 보드에 기록하지 않았다.
