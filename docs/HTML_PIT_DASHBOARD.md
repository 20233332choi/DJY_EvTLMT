# HTML 피트 대시보드

## 실행과 공유

- 통합 BAT의 **1번은 Rear STM USB 직접 수신**, 2번은 로컬 ESP UDP, 7번은 ngrok입니다.
- 피트 PC: `http://127.0.0.1:8766/pit`. `/` 및 `/tuning`도 같은 화면입니다.
- 팀 공유: 현재 ngrok HTTPS 주소 + `/pit`. ESP 릴레이 주소는 기존 `/api/vehicle/exchange`를 유지합니다.
- `/driver` 운전자 화면, `/phone` GPS 전송, `/records` 전체 JSON 조회는 유지됩니다.
- 기존 TQV 제한/강도 제어와 실측 에너지 파일 분석: `run_dashboard.bat native`.

## Rear STM USB 직접 기록 (무선 보류)

`Front → CAN → Rear → ST-Link USB → PC → HTML/SQLite` 경로입니다. ESP는 사용하지 않습니다.
Rear의 ST-Link USB를 PC에 연결하고 통합 BAT의 1번을 선택합니다.
ST-Link 포트가 하나면 자동 선택하며, 여러 개면 `run_dashboard.bat wired COM13`처럼
실제 Rear 포트를 지정합니다. Front 포트에 연결하면 Rear 문장이 없으므로 미수신으로 표시됩니다.

- 상단에 `STM USB COM13 · … Hz 수신`이 보이는지 확인하고 **측정 시작**을 누릅니다.
- 측정 종료 후 과거 세션 및 `/records`에서 확인합니다. DB는 기존 `data/ev_telemetry.db`입니다.
- RPM/TPS/IMU, DAC, TQV 내부 9개 값과 진단 필드를 저장합니다. 원문은 `stm_raw_line`,
  모든 원본 키/값은 `stm_fields`에 보존합니다. 오류값도 삭제하지 않습니다.
- `vs/dy/ye/dp/pl/pr/tr`은 STM의 정수 milli 단위를 1,000으로 나눠 원래 단위로 복원합니다.
- 현재 Rear 출력은 약 5Hz입니다. STM 내부 100Hz 제어 샘플 전체가 전송되는 것은 아닙니다.
  원본 로그에는 시간/시퀀스가 없으므로 `timestamp_source=PC_MONOTONIC`,
  `sequence_source=PC_RECEIVE`로 구분합니다. 그래프 시간축은 PC 수신 시각입니다.
- IMU는 `imu=1`인 실제 출력만 표시합니다. 조향각은 raw값만으로 유효성을 알 수 없어
  명시적인 `sas_ok=1`이 없으면 그래프에서 미수신으로 남깁니다.
- RPM은 연속 캡처 증가량 중 절반 이상이 glitch이면 **노이즈 의심**으로 품질 통과 그래프를 숨깁니다.
  이는 보수적인 표시 기준이지 센서 품질 인증이나 제어 필터가 아닙니다. 새 펄스가 없으면
  정지와 단선을 구별할 수 없으므로 정상 0RPM으로 단정하지 않습니다. **STM 보고 RPM · 검증 전**
  채널은 이때도 받은 숫자를 점선으로 표시합니다. 품질/폐기 비율을 함께 보며 실제 RPM으로 단정하지 않습니다.
  원본 RPM은 측정 시작 이후 DB에 남습니다.
- USB를 뽑으면 마지막 값을 현재값으로 표시하지 않고 약 1.5초 후 미수신 처리합니다.
- 이 모드는 읽기 전용이며 UART에 명령을 쓰지 않고 DTR/RTS를 비활성화한 뒤 엽니다.
  UDP 수신/차량 릴레이 입력은 시작하지 않으며, `--enable-control`과 동시 실행할 수 없습니다.
  측정 중에는 런처가 입력을 교체하지 않습니다. 먼저 측정을 종료해야 합니다.

## 그래프

현재 피트 UI는 검정(#000000) 배경과 밝은 원색의 3px 선을 사용합니다.
Yaw(목표/실측/STM 오차), 전력(좌/우/차동), RPM(측정/보고/목표), km/h 차속,
조향, 스로틀, traction_scale, TV/ED 상태, 모터 전압의 9개 독립 패널입니다.
같은 패널은 같은 단위 축을 공유하고, 모든 패널의 시간 탐색/커서는 동기화됩니다.
상단 TQV 카드에는 원래 C 변수명과 단위, 기존 수신 필드임을 표시합니다.
`yaw_error`는 STM 전송값이며, 별도 `화면 계산 오차`와 구분합니다.

PID Kp/Ki/Kd는 Rear가 보낸 `kp/ki/kd`(milli 단위)를 표시합니다. USB/ESP 모두 지원하며
보드가 이 필드를 보내지 않거나 만료되면 **미수신**입니다. 현재 소스의 20/1/0을 UI 기본값으로 넣지 않습니다.
새 Rear 펌웨어, 무선은 새 ESP 펌웨어까지 필요합니다. 화면의 PID는 읽기 전용입니다.
계수는 원본 JSON/과거 조회/CSV에도 보존됩니다.

`vehicle_speed` 카드(m/s)는 STM 계산 원본이고, 큰 차속(km/h)은 `speed_online` 통과값입니다.
기어비 4:1, 타이어 폭 42라는 사용자 정보만 확인되었습니다. 폭으로 지름을 추정하지 않으며,
현재 소스 반경 0.2286m와 실제 바깥지름/둘레의 일치는 미확인입니다. 차속 교정 완료를 뜻하지 않습니다.

2026-09-12 유선 적용 검증: COM13 실제 수신 약 5.04Hz, 검증 세션 #1에 28개 원문 포함
기록 저장 및 TQV 9개 필드 확인. 자동 테스트 50개와 Edge 그래프/과거 조회/CSV/기록 버튼
검사 통과. 검증 세션은 종료했고 이후 측정은 사용자가 **측정 시작**으로 시작합니다.
보드 펌웨어는 변경하지 않았습니다. 이는 센서 자체의 정상 동작이나 차량 구동 검증이 아닙니다.

| 신호 | 패킷 필드 | 유효 조건 |
|---|---|---|
| 목표 yaw rate | desired_yaw_rad_s | tqv_internal_online |
| 현재 yaw rate | yaw_rate_rad_s | imu_online, imu_ok |
| 좌/우 RPM | rpm_left / rpm_right | rpm_*_online, motor_*_ok |
| 좌/우 STM 보고 RPM (검증 전) | rpm_left_reported / rpm_right_reported | 해당 원본 필드의 신선한 수신 |
| 좌/우 목표 RPM | rpm_left_target / rpm_right_target | 명시적인 목표값 수신, 0..65535 |
| 좌/우 전력 명령 (실측 아님) | power_left_kw / power_right_kw | tqv_internal_online 및 해당 필드 수신 |
| 좌/우 모터 전압 | motor_left_voltage_v / motor_right_voltage_v | motor_*_voltage_online |
| 조향각 | sas_deg | sas_online, sas_ok |
| 스로틀 개도량 | tps_pct | tps_online, tps_ok |

체크박스 상태는 브라우저에 저장됩니다. 그래프를 숨겨도 기록은 유지됩니다.
각 패널은 독립 Y축과 단위, 선 색상 범례를 갖습니다. 체크박스로 개별 선을 켜고 끕니다.
TV/ED와 트랙션 배율은 0..1 고정 범위이며 나머지는 해당 패널의 표시값에 맞춰 자동 조정합니다.
포인터, 값 표시, 오차 계산, CSV, DB는 원래 값을 사용합니다.
현재 오차는 목표-현재, RMS는 표시 구간의 유효한 수신 샘플 쌍으로 계산합니다.
미수신·오류·1.5초 초과 공백은 선을 연결하지 않습니다. 유효한 0 RPM은 0으로 그립니다.
전압이 없는 현재 펌웨어에 대해서는 값을 만들지 않습니다. 팩 전압과 모터 전압은 별개입니다.

### RPM 값의 출처와 목표값

- 현재 빌드 기준 `rpm_sensor.c`의 `s_rpm_l / s_rpm_r` → `RPM_GetLeft/Right()` →
  USB 문장의 `L / R` → `rpm_*_reported`는 같은 계산값입니다. `reported`는 펄스 파형이나
  필터 전 `RPM_GetLeftRaw/RightRaw()`가 아닙니다. IDE에서 보던 변수가 무엇인지는 별도 확인이 필요합니다.
- `rpm_left / rpm_right` 품질 통과 채널과 보고값 채널은 같은 수신 숫자를 사용하지만
  품질 통과 채널에만 기존 보수적 표시 조건이 적용됩니다. 표시 조건을 통과해도 실제 RPM 보정 완료를 뜻하지 않습니다.
- 현재 `TV_t`에는 목표 RPM이 없고 `power_left/right` 및 DAC를 출력합니다. 따라서 현재 목표 RPM은
  **미제공**입니다. 스로틀×최대RPM이나 kW→RPM을 만들어 넣지 않으며 TV/ED 제어 로직은 변경하지 않았습니다.
- 수신 준비 필드: JSON은 `rpm_left_target`, `rpm_right_target`, Rear 텍스트는 선택 필드
  `rpm_target_l`, `rpm_target_r`(0..65535)입니다. **현재 STM은 이 선택 필드를 송신하지 않습니다.**
  유효성 false, 결측, 오래된 목표는 0이 아니라 미제공으로 표시합니다. 목표값 송신/속도제어 추가는 별도 작업입니다.
- 모터 비교 카드, Scope 포인터 및 과거 페이지는 같은 시점의 값/품질을 표시합니다.
  CSV에도 `rpm_*_quality`, `rpm_*_rejected_pct`, `motor_command_mode`를 포함합니다.
  기존 DB의 원본 JSON은 유지하며 새 표시 채널이 없던 과거 데이터에 값을 채워 넣지 않습니다.
- 설치 빌드 기준 RPM 소스/설정은 `DJY_TQV` 작업본과 비교해 동일했습니다. 그러나 백업한 다른 팀의
  바이너리와 원래 IDE 프로젝트의 동일성은 확인되지 않았습니다. 현재 설정 `RPM_PULSES_PER_REV=11`,
  `RPM_CAL_GAIN=17.45`와 컨트롤러 SPD 신호 설정/실회전수의 일치는 아직 재검증이 필요합니다.

## 기록과 과거 조회

2026-09-12 23:28 이후 RPM 표시 적용 확인: 읽기 전용 COM13 약 5.04Hz, API 14채널 및
실제 브라우저의 좌/우 보고값 표시 확인. 당시 좌 0(새 펄스 없음), 우 약 7,970(노이즈 의심,
구간 폐기율 99.3%), 목표 RPM은 양쪽 미제공이었습니다. 사용자는 모터 정지 상태라고 확인했습니다.
따라서 실제 RPM 측정 정상화/보정은 완료되지 않았으며, 컨트롤러 고장을 판정한 것도 아닙니다.
보드 펌웨어와 구동 설정은 이번 표시 수정에서 변경하지 않았습니다.

- Python 52개 테스트 및 Edge 14채널/품질/목표 결측/과거/CSV/모바일 검증 통과.
  전체 테스트의 Windows HTTP 연결 중단 오류는 재실행 시 재현되지 않았습니다.
- PC 수신 프로그램 재시작 전에 그래프 버퍼 12,000점을
  `.local/rpm-scope-before-update-20260912.csv`로 내보냈습니다(22:42:12~23:26:13 KST).
  23:04:59~23:06:37의 스로틀 입력(최대 95%)이 포함됩니다. 당시 미측정 RPM 등은 빈칸이며
  이 CSV를 전체 원본 로그나 DB 측정 세션으로 간주하지 않습니다. 당시 DB 기록은 꺼져 있었습니다.

측정 시작부터 종료까지 기존 `data/ev_telemetry.db`의 세션/원본 패킷 기록을 사용합니다.
모터 전압을 비롯한 추가 필드도 `payload_json`에 보존됩니다. 체크박스나 접속자 수는 기록량에 영향을 주지 않습니다.
화면 일시정지는 브라우저 표시만 정지합니다. 피트의 기록은 계속됩니다.
과거 세션은 처음부터 1,000개씩 조회하고 이전/다음 페이지와 시간 슬라이더로 탐색합니다.
한 번 선택한 세션은 조회 시작 시점의 마지막 ID까지 고정되어, 동시 기록에도 페이지가 밀리지 않습니다.
기록 중 세션의 새 데이터를 다시 읽으려면 실시간으로 전환하거나 세션을 다시 선택합니다.
CSV는 현재 메모리 페이지 전체 신호를 내보내며, 숨긴 신호도 포함합니다. 미수신은 빈칸입니다.

실시간 메모리 버퍼는 최근 12,000개 수신 이벤트이며 재시작 시 초기화됩니다.
DB 기록은 버퍼와 별개로 유지됩니다. 세션 선택 목록은 최근 500개입니다.
웹은 최대 약 4회/초 갱신하며, 그 사이 도착한 수신 이벤트를 커서로 한꺼번에 읽습니다.
ESP→피트 구간에서 이미 유실/병합된 샘플을 브라우저가 복원하지는 못합니다.
현재 릴레이는 매 HTTP 교환에 최신 패킷 하나를 보내므로 센서 내부 제어주기 전체를 기록한다고 볼 수 없습니다.
PID 판정에는 실제 수신 간격, 원본 timestamp_ms, 패킷 누락을 함께 확인해야 합니다.

## 접근 경계

`/api/tuning/live`, `/sessions`, `/samples`, `/overview`는 공유 주소에서도 읽을 수 있습니다.

ngrok 주소를 아는 사람은 이 읽기 화면과 세션 이름을 조회할 수 있으므로 팀에만 공유합니다.
